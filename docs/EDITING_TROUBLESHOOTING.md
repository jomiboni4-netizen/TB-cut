# 直播商品剪辑：跨窗口问题与解决方案

更新日期：2026-10-12。

本复盘归纳多窗口剪辑、成片修复、导出和表格回填中实际遇到的问题。公开内容只保留可复用的原因、处理方法和验证边界；原始字幕、商品信息、媒体路径、时间线快照及运行数据保留在本机。

“本机已验证”指窗口记录或本地验收支持该结论，不表示相关实现已经进入 GitHub。本次提交只发布本文档与固定审查报告；工作区已有的脚本、规则和测试改动仍需另行审查提交。

## 1. 跨窗口接手与批次身份

### 状态文件与实际进度不一致

- **问题**：主状态仍指向较早批次；另一窗口的审核或写入已经完成。旧缓存存在，但不能证明可用于当前任务。
- **解决方案**：接手时读取规则、状态和本批报告；使用独立工作区及固定批次身份；对照输入指纹、审核记录和当前时间线。
- **验证边界**：先区分“已审核”“已写入”“已导出”。遇到既有商品标记，回读核对源范围，不能直接重复追加。

### 旧派生成果身份失效

- **问题**：编号规则、输入或商品边界改变后，旧方案仍留在本机；沿用它会造成串批或错位。
- **解决方案**：保留历史成果，但让身份校验拒绝复用；从可信上游重建受影响链路。导出当前时间线时建立独立的新快照，不能给旧剪辑缓存重新贴身份。
- **状态**：缓存隔离和拒绝旧身份已在本机流程中使用；本次不认证历史缓存。

## 2. 商品编号、边界与候选池

### 空标题导致商品编号压缩

- **问题**：跳过空标题后重新编号，使标题表行号与时间线标记不一致；标记备注还可能保留旧编号。
- **解决方案**：编号按原工作表数据行位置确定，空标题保留占位；用字符串商品 ID 对照旧成果，保留前导零。
- **验证边界**：先校验 ID 唯一性、表头及实际工作表；匹配商品以 ID 为准，不能仅信旧备注中的序号。

### 自动锚点不等于完整商品范围

- **问题**：链接提示不清晰、出现串品或缺少下一起点；标题表顺序也未必等于直播顺序。
- **解决方案**：自动结果只作建议；人工确认本批源文件内的完整起止范围，再做真实时间顺序和跨商品重叠检查。
- **验证边界**：标题匹配只提供线索。范围确认后扫描完整候选池，不能只剪锚点附近。

### 可用内容不足与审核模型失败

- **问题**：清理禁用内容后，有些商品无法形成三条独立且不重复的合格成片；远端或本地语义模型也曾没有返回可用结果。
- **解决方案**：锁定通过版本，搜索完整剩余候选池并返修；只有耗尽后才减条数。当前语义选择默认由 Codex 完成；MiMo 仅在用户明确改变默认并授权数据范围后使用。
- **验证边界**：通用连通性探针成功不代表实际失败请求已修复；模型标识迁移也不能代替故障复现。记录失败类型，不补重复内容凑条数。

## 3. 语义完整性与物理切点

### 同为 Codex 语义审核，前一轮仍漏掉句尾不完整

- **已发生的问题**：前期选段和语义审核由 Codex 完成，但实际剪辑仍出现末尾话未说完整；后续成片检查与修复也由 Codex 完成，才补齐句尾。这是前一轮审核漏检，不是更换审核模型解决了问题。
- **原因边界**：选段文本或粗时间范围逻辑完整，不能证明经过物理切点处理后的成片仍保留完整话语。现有记录支持前一轮检查不足，不能据此断言每个缺陷都来自同一种切点算法。
- **解决方案**：将选段审核与成片终审分别记录。Codex 在终审中以最终保留范围检查独立开头、完整结论及接缝依赖，本机语音识别、停顿和音量检测辅助核对实际句尾；失败后修复并重审。
- **验收要求**：不沿用选段 PASS 代替成片 PASS。最终范围调整后，重新核对完整话语和相关硬规则，并通过时间线回读确认实际写入范围与终审方案一致。

### 句首、句尾和上下文被切断

- **问题**：首句依赖删掉的前文，结论或尾音未保留；金额、促销、展示指令混入商品讲解。
- **解决方案**：先修语义范围，再对保留窗口做本机语音识别、停顿和音量复核。完整句尾需延长时，替换其他低价值完整段落，而非截断句子压时长。
- **验证边界**：连接词触发上下文检查，不机械删除。承诺展示的内容若已在画面兑现，应核实后保留。

### 时间码、帧率与多余拼接点

- **问题**：字幕时间只是粗边界；素材帧率、方案帧率和时间线帧率不同，直接复用帧数会错位。语义标签也可能制造无意义切点。
- **解决方案**：通过时间换算各帧域；在最终帧边界复核起止。相邻同源、未删内容且连续的片段合并，语义角色保留为审核记录。
- **状态**：本地写入与回读记录支持帧率换算及合并方案；这些工作区实现尚未随本文档提交。

## 4. 人物检测与画面误报

### 有人物的画面被报为零

- **问题**：Apple Vision 在沙盒内出现模型加载或像素缓冲区错误，早期工具将执行失败误当作无人画面；缓存二进制也可能落后于源码。
- **解决方案**：在沙盒外运行人物检测；失败时停止并显示底层错误；源码更新后重建探测程序。先用明确有人与空白样本检查工具，再审核候选画面。
- **验证边界**：环境错误不是人物占比结果。已保存的旧零值不能直接用来否决或放行成片。

### 静止站姿、特写和粗抽样的限制

- **问题**：静止展示被报为冻结；商品特写虽然有价值，但未必满足主播可见比例。Qwen 粗抽样曾用于本地复核。
- **解决方案**：对疑似冻结检查原分辨率连续帧；替换有明确缺陷的片段，保留正常版本。Apple 检测优先，必要时使用本地 Qwen 复核不确定画面。
- **验证边界**：少量抽样全有人，不能等同于全片人物比例。接近阈值时加密检测；最终仍须严格超过人物比例门槛。

## 5. 达芬奇连接、写入与时间线修复

### 新窗口误判达芬奇无法连接

- **问题**：默认本机入口返回空，即使软件和脚本服务已运行；仅测试该入口就要求用户改偏好设置，遗漏了有效的网卡地址回退。
- **解决方案**：统一连接入口，沙盒外只读检查；动态尝试本机、回环和当前网卡地址，有限重试并重新取得对象。指定主机时遵守指定范围。
- **验证边界**：连接成功后核对项目和源、目标时间线；连接重试不自动重放写入。只有完整诊断后才说明阻塞原因。

### 重复追加与补句尾碰撞

- **问题**：已有商品标记却继续追加；补全句尾后与下一成片相撞；后移范围选错会波及无关商品。
- **解决方案**：写前回读并备份。按用户授权，仅在发生碰撞时同步后移时间上后续的音视频和关联标记；保持顺序、源范围、属性和原有间隔。
- **验证边界**：按真实时间位置选后续范围，不能只按商品编号。执行后独立回读，检查源时间线、未受影响片段、标记、同步和数量。

## 6. 计算耗时与缓存复用

- **问题**：反复识别将被替换的段落、重复加载模型、重复检测相同源画面，使修复耗时增加。
- **解决方案**：先确定语义修复，再集中进行局部语音和画面审核；合并同素材重叠窗口，模型按需加载。人物缓存绑定素材身份、精确范围和检测器指纹。
- **验证边界**：缓存只复用检测数据，不代替当前方案终审或写入授权。记录命中、新计算量和各阶段时间；没有整轮测量，不声称整体提速比例。

## 7. 导出、重新导出与表格回填

### 结尾空隙、文件命名和导出设置

- **问题**：按商品标记区间直接导出会带上成片间空隙；标记名称可能含说明文字，不能直接作为商品 ID；部分渲染设置值不被 API 接受。
- **解决方案**：从最新时间线的连续画面建立导出清单；从已核对的商品身份取 ID，文件命名为 `商品ID_序号.mp4`。导出终点为最后保留画面的帧，API 的包含末帧范围需减一。
- **验证边界**：核对单片导出模式、尺寸、帧率、音频和设置返回值；导出后检查实际视频帧数、音轨、文件集合和末尾画面。

### 用户调整画面后全部重新导出

- **问题**：导出中途取消，随后用户调整画面；旧任务或旧文件混入会让交付版本不一致。
- **解决方案**：取消后先等用户决定；得到从头导出的指令后，重新读取画面属性和设置，确认旧文件状态，建立新队列，只启动本次任务。
- **验证边界**：以新快照及输出验收为准。历史写入数量可能与当前成片数量不同；导出检查通过不表示时长、语义和去重硬审自动通过。

### 剪辑条数回填标题表

- **问题**：按行号或旧编号回填容易错行；整本工作簿重新导出可能改变未授权的格式或结构。
- **解决方案**：按商品 ID 汇总已验证成片，写入现有“剪辑”字段；无成片的 ID 填零。保留原表备份，仅替换目标数值。
- **验证边界**：所有导出 ID 必须匹配，ID 不可重复，总数与清单一致；保存后回读，并核对未编辑内容和工作簿其他部分不变。

## 8. 已验证方案与后续缺口

- **已有本机证据**：网卡回退连接、既有写入回读、句尾修复与同步后移、Vision 沙盒外检测、局部计算复用、重新导出验收、按 ID 回填条数。
- **公开基线已有**：批次身份与商品范围确认门禁。其他实现的发布状态以 Git diff 和提交记录为准，不凭窗口汇报认定已发布。
- **环境缺口**：项目检查仍遇到工作簿依赖锁与现有运行包版本不一致。可直接使用当前运行包完成窄范围表格任务，不等于依赖门禁已修复；不静默改锁或认证全部流程。
- **流程缺口**：部分操作仍在本地运行脚本中完成；需另行抽取为可复用入口并补适当验证。导出取消后的恢复、最终画面设置快照、字段回填都应纳入该整理。
- **审核缺口**：导出与标题表回填只是交付验收；严格时长边界、全片人物比例及最新时间线的全部剪辑硬审须分别确认，不能沿用较早窗口的总体验收结论。

### 依据与使用方式

本复盘交叉核对了初剪、断点恢复、模型诊断、多组成片修复及当前导出窗口的汇报，并对照 `PROJECT_RULES.md`、本地脚本和验收记录。聊天汇报用于定位问题；源码、身份校验及当前验收决定操作是否可继续。

接手者先读取规则与状态，再按本文对应问题定位处理方法。本文不是写入授权，也不是完整的一键流程。真实项目和成果记录不进入公开文档。
