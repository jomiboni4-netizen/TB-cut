# 口播剪辑自我迭代计划

## 目标

针对剪辑点不自然和反复修改造成的流程退化，建立可复现、可比较、可回退的改进闭环。计划完成前保留本文档；本地四阶段完成并验收后，按用户要求删除本文档及对应 GitHub 计划文件。

## 阶段一：只读盘点与止损

- 检查当前 Git 分支、工作区改动、远端和近期历史；不覆盖、清理或提交既有本地改动。
- 梳理从输入、字幕/语义处理、候选选择、切点决策到 Resolve 写入和导出的真实流程。
- 标出近期影响剪辑质量或稳定性的代码变更、现有测试和缺失证据。
- 输出可复现基线候选、依赖与风险清单；未确认前不重构核心算法。

**验收：**结论引用实际文件、提交或测试证据；明确哪些事项尚不能复现或判断。

## 阶段二：基线与质量评测

- 选定可复现代码版本、依赖、运行参数和固定素材；素材身份与人工标注可追溯。
- 先从一段已知问题口播和一个切点建立最小样本，再决定是否扩展素材集。
- 将评测分成两个独立问题轴：①切点吞字/截断；②主播短时间内重复用词或重复表达同一意思时，能否保留最完整、最有信息量的一次并压缩冗余。
- 吞字风险使用词级 ASR 时间戳与局部音量/静音边界联合筛查；音量只作风险信号，不能单独证明字词完整，边界争议仍须回听局部音频。
- 重复表达先区分字面重复与语义重复；评测目标是删减冗余完整表达，同时保住信息和自然衔接，不以关键词删除或机械缩短句子代替语义判断。
- 区分确定性错误、机器风险提示和必须人工判断的自然度，不伪造客观评分。
- 检查时间轴、语音截断风险、音频拼接、语义闭合、音画同步和运行稳定性；记录各项检测能力边界。
- 固定评测规则与标签，实验修改不得同时改变评测标准或测试标签。

**验收：**相同基线可重复运行；报告能指出证据、限制和人工复核项。

## 阶段三：单变量隔离实验

- 每轮只提出一个问题和一个主要改动假设，在独立任务分支或 worktree 修改。
- 使用同一输入生成基准版与实验版；运行相关自动检查并比较局部切点样片。
- 自动检查不得把主观自然度包装成确定结论；记录修改、指标、回归和复现信息。
- 未通过则保留失败原因并放弃实验变更；通过只形成待审 PR，不自动合并或发布。

**验收：**实验可复现、差异可审查、退化可阻止，原基线可恢复。

## 达芬奇用户反馈闭环

- 至少三轮代码修订并通过合成检查后，进入单独的真实项目验收；每个候选版本先通过现有硬门禁，再写入经用户确认并登记的“实现/审核线”，由用户回看并按商品与时间点反馈。
- `AI cut` 等源时间线只读。试错版本不直接覆盖 `成品`；用户认可的版本再按项目现行规则进入最终成品流程。
- 每轮使用明确版本/方案摘要，写前备份、写后回读校验；保留已认可版本，避免并发修改和把旧审核结论复用到新方案。
- 若“实现线”尚不存在或未登记，先由用户明确确认目标项目与时间线；不得猜测项目、自动新建或写入。
- 用户反馈只触发对应局部复核和修订；每次改动后重跑受影响的硬门禁，全部通过后才可再次写入审核线。

## 阶段四：受控迭代与停止

- 以阶段三闭环稳定为前提，至少完成三轮有证据的代码改进；通常三轮结束，只有明确阻塞时才延至第 4 或第 5 轮，绝不超过五轮。该上限沿用项目规则，不替代质量门槛。
- 每轮报告问题、假设、改动、前后证据、回归、结论和下一步。
- 连续失败、无法复现、质量退化、测试异常或资源超限时停止并保留记录。
- 不自动降低门槛、合并主分支或对生产时间线写入。

**验收：**每轮都有可核验结论；没有证据时明确停止，不宣称已改善。

## 总体验收与清理

四阶段完成后，复核计划各项验收证据、未解决风险和 GitHub PR 状态。仅在本地闭环完成后，删除本计划文件及 GitHub 上的对应计划文件；保留源代码、测试和必要实验记录。清理动作作为最后一步记录。
