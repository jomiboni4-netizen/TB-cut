# 剪辑耗时与重构交接（2026-10-22）

## 已观测的下一批运行

批次 7–9 的调度器有 7 次商品分析事件，累计约 1152 秒；其中包含真实剪辑、代码修复后的重跑和缓存复核，不能当作正常无故障批次的基准。商品级记录累计约 1084 秒，二者统计口径不同，不可相加。

| 商品级阶段 | 调用累计耗时 | 解释 |
| --- | ---: | --- |
| Codex 选段 | 333.5 秒 | 多次修复或依赖失效后重新执行 |
| 局部 ASR | 439.0 秒 | 模型识别、局部窗口及重试；含缓存复核 |
| Codex 语义终审 | 134.3 秒 | 选段变化后重新绑定语义证据 |
| 人物审核 | 84.5 秒 | 含返修后抽样复核 |
| 物理方案 | 7.4 秒 | 本身不是主要耗时 |

标题和字幕索引各运行 9 次，累计分别约 2.4 秒和 2.4 秒；不是优先优化对象。两次 Resolve 追加累计约 36.6 秒，额外事务回读恢复约 13.1 秒。以上数字来自本机批次事件与商品阶段记录，四舍五入；阶段计时可能包含其子调用，不能直接求和声称总墙钟。

## 已修复的返工源

1. 剪映字幕时间只作附近搜索提示。近音品牌、错字和口语连接词由局部 ASR 词组核对，最终切点仍受完整词界及声音证据约束。避免将正常近音差异误判成整条视频失败。
2. 局部 ASR 重试会从已审核粗选恢复卖点映射；旧的选段修复次数不再挡住保留语义证据的局部切点重试。
3. Resolve 追加成功但记录回执失败时，通过调度器回读现有事务恢复，绝不重复追加。调度器子进程使用 UTF-8，避免中文回执在 ASCII 环境下误读。

## 后续重构优先级

1. **分阶段依赖身份**：当前商品检查点把多份脚本和整份规则文件纳入广域指纹。无关代码/规则改动可能迫使选段、ASR、语义和人物证据重新计算。先列出每阶段真实依赖，再逐阶段迁移和验证；不得直接放宽身份校验或把旧证据重盖为 PASS。
2. **ASR 边缘诊断**：在返修任务中记录具体失败切点、字幕锚、邻近词组和匹配策略的脱敏摘要，使下一次只修对应边界，避免多轮完整调度后才定位错字。字幕与 ASR 同音容错只在限定时间窗内生效，继续保留歧义拦截。
3. **选段与语义证据复用**：只有候选池、选中字幕所有权或语义实际变化时才重新调用 Codex；纯物理切点返修继续复用已通过语义回执。按阶段分别记录缓存命中、失败原因及墙钟耗时。
4. **人物审核复用**：受影响版本单独重算；相同源画面、检测器和抽样策略可复用原分类证据，但最终比例仍绑定最终物理方案。
5. **交付事务与报表**：把追加、写后回读、异常恢复作为调度器显式状态，记录每次是否真正写入。批次报告分别列出剪辑计算、返工、等待、Resolve 交付耗时，避免把开发修复时间归作单品剪辑效率。

下一批优先完成真实素材落线，遇到可复现故障才针对失效阶段修复。记录下一批无故障时的实测墙钟，再与本批含返工数据比较；不预先宣称提速幅度。音频增益只有在已验证可写、可回读的 Resolve 接口存在时才处理；若无可靠接口，记录为未调整，不阻塞本批写入。
