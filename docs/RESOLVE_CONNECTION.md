# 达芬奇连接与恢复

在项目目录执行只读检查：

```bash
python3 scripts/resolve_connection_doctor.py --root .
```

Codex 在 macOS 上须在沙盒外运行此检查。此脚本不会打开、关闭、切换或修改项目，也不会更改偏好设置。

所有项目入口使用同一连接实现。每次先尝试本机 API；没有指定主机时再尝试回环地址、当前 `en0`、当前 `en1`。一个网卡失败不阻止另一网卡。显式设置 `RESOLVE_HOST` 时，只尝试本机与指定主机，防止静默连接其他机器。地址每轮重新读取，不保存旧地址作为下一次连接依据。

连接最多重试四轮，每轮之间等待一秒；连接到的对象必须能读取项目管理器。每次调用重新连接，不复用达芬奇关闭前的对象。默认只读检查在独立进程内运行，二十秒超时；原生调用挂起或检查进程崩溃时会报告失败。可用 `--timeout` 调整检查超时。业务脚本本身的原生 API 调用没有 Python 超时保证。

返回 `connected` 表示 API 已连接；`ready` 还要求有打开的项目，并与本地状态中的项目和时间线配置相符。连接成功不代表可以跳过写入前审核。

本地诊断位置：`.cache/resolve_connection_status.json`。只记录路线名称、重试轮数和状态，不记录网络地址或项目内容；该文件不提交。

失败分类：

- `api_unavailable`：API 模块或原生库不可加载。
- `app_not_running`：重试后仍无法连接，且未检测到达芬奇进程。
- `api_not_ready_or_inaccessible`：未就绪或访问受限，不能单凭此状态断言偏好设置错误。
- `no_project_open` / `project_mismatch` / `timeline_configuration_mismatch`：API 已响应，但当前项目不满足任务配置。
- `connection_check_timed_out` / `connection_worker_failed`：原生检查超时或进程异常。

程序关闭期间没有服务可连接。重新打开后再执行统一检查即可；若仍失败，按诊断处理。连接重试不包含业务写入，避免断线后重复追加片段。写入失败必须先回读已有结果再决定修复。

自动测试模拟关闭、重开、启动延迟、网卡变化、失效对象及检查超时。不会为测试关闭用户当前的达芬奇项目。
